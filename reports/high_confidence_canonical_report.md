## 3. Canonical Audit — 5-Point Check Results

### 3.1 Rejection Reason Breakdown

### 3.2 Deep Analysis of the 707 Canonical Mismatches

The dominant failure reason (`canonical_answer_mismatch`) requires nuance. FinQA's official answer is the **final computed result** of a multi-step program (e.g., `divide(A, subtract(B, C))`), whereas Gemini's `<mark>` value often corrects an **intermediate lookup error** — a wrong table cell or raw value.

| Subcategory | Count | Description |
|---|---|---|
| `fully_ungrounded` | 497 | `<mark>` value is neither in the context nor close to the canonical answer |
| `grounded_intermediate` | 132 | `<mark>` value appears verbatim in the source context (correct lookup, wrong final answer) |
| `very_close_to_canonical` | 41 | `<mark>` value is within 5% of the canonical answer (rounding/formatting difference) |
| `yes_no_question` | 30 | Canonical answer is "yes"/"no" — incompatible with numerical correction format |
| `delete_grounded_mark_computed` | 7 | `<delete>` is grounded, `<mark>` is a plausible but unverifiable computation |

**Of the 132 grounded intermediates**, 44 have **both** `<delete>` and `<mark>` appearing in the context — these are high-quality **table-cell swap errors** where Gemini correctly identified the wrong cell was pulled.

> [!IMPORTANT]
> **180 rows** (132 + 41 + 7) are potentially salvageable but fail strict canonical verification. These are excluded to maintain dataset integrity. Only the 447 rows where the `<mark>` value demonstrably matches the official FinQA answer are retained.

## 5. Verdict: Are the Existing 1,155 Rows Sufficient?

### Answer: **No.**

The hybrid dataset plan requires:
- **5,000–6,000** corrupted examples
- **1,000–1,500** clean examples

### What We Have

| Category | Count |
|---|---|
| Canonical-valid Gemini examples | **447** |
| Clean (pass-through) examples | **0** |

### Gap Analysis

| Need | Have | Deficit |
|---|---|---|
| 5,000–6,000 corrupted | 447 Gemini | **4,553–5,553** to generate deterministically |
| 1,000–1,500 clean | 0 | **1,000–1,500** to extract from official FinQA |

### Recommendation

1. **Retain** the 447 canonical-valid Gemini examples as natural-language corrupted training data — these provide linguistic diversity that deterministic generation cannot replicate.
2. **Supplement** with **4,553–5,553** deterministic Python-generated numerical/temporal errors using official FinQA rows as source material:
   - Draw from **all three splits** (train/dev/test) proportionally
   - Heavily target **temporal errors** (currently 0.7% → aim for 15–20%)
   - Apply single-value corruption: swap table cells, perturb percentages, shift years
3. **Generate** **1,000–1,500** clean pass-through examples where the response already matches the canonical answer (no XML tags in target).
4. **Remove** free-form Chain-of-Thought (`Reasoning: ...`) from the primary training format — use only the `Correction:` block with XML tags.
5. **Enforce** exactly one `<delete>`/`<mark>` pair per target across the entire dataset.
